@uh ABSTRACT

@pa Application programming interfaces (APIs) carry most of the traffic between clients and the services that hold user data, which makes them a frequent target for token theft, replay, broken authorisation and injection. This project builds and tests a secure API web application, the Secure API Communication Platform, in which no single check is trusted on its own. A Node.js gateway verifies RS256-signed JSON Web Tokens, scopes and rate limits. A Python FastAPI service verifies the same token again and accepts requests only over mutual TLS with an HMAC-SHA256 signature, a timestamp and a single-use nonce. A PostgreSQL database is reached only through parameterised queries under a least-privilege role. Signing keys and database credentials come from HashiCorp Vault, and structured logs feed a React security dashboard and Grafana. The system was validated with 26 unit tests, 19 live request flows and an attacker toolkit of 28 checks covering replay, token forgery, brute force, injection and TLS downgrade. Testing also exposed real weaknesses: login timing revealed which usernames exist, account lockout could be used to lock out a known user, two of three Grafana panels were broken, and the attacker runner could not reproduce its own result. These five were fixed and re-tested; the remaining limits of a development-mode deployment are reported openly.
